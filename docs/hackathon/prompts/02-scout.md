STEP 3. Create apps/web/lib/scout/analysis.ts with pure functions (no LLM) that compute a TrustSignals object from a trust profile plus its feedback list:
  - liveness: has registrationFile, has any endpoint fields (mcpEndpoint, a2a, etc, whatever the schema has), registration age in days.
  - feedbackByTag: for each tag1, count, min, max, mean of value. Never average across tags.
  - distinctClients: count of unique reviewer addresses, and concentration ratio = totalFeedback / distinctClients.
  - burstiness: fraction of feedback created within the single busiest 24 hour window.
  - flags: array of strings from these rules, each with a one-line reason: SINGLE_CLIENT_DOMINANCE if one client gave more than 50% of feedback; HIGH_CONCENTRATION if ratio > 5; BURST if burstiness > 0.7 and totalFeedback >= 10; NO_METADATA if registrationFile is null; NO_ENDPOINTS if no endpoints advertised; VALIDATION_UNAVAILABLE always on chains with no validation registry (this is true on all live chains right now); NAME_LOOKALIKE if the name matches a pattern of an @handle of a well-known brand or public figure (keep a small list, this is heuristic, label it as such).
  Write unit tests for the flag rules with the project's existing test runner.
